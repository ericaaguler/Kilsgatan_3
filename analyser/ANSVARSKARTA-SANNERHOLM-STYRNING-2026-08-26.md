# Ansvarskarta – metod och styrning

**Datum:** 26 augusti 2026  
**Syfte:** Styra arbetet med en fullständig ansvarskarta för Familjebostäders hantering av Kilsgatan 3, lägenhet 1202.

## Metodologisk utgångspunkt

Arbetssättet är inspirerat av frågor om ansvar, ansvarsutkrävande och offentlig verksamhet där Richard Sannerholms forskning används som metodologisk utgångspunkt. Detta innebär **inte** att Sannerholm tillskrivs någon uppfattning om det konkreta ärendet och inte att analysen ska imitera honom.

Ansvarskartan ska rekonstruera:

`vem hade ansvar? → för vad? → vad fick personen/funktionen kännedom om? → när? → vad gjordes? → på vilket underlag? → vad blev resultatet? → hur följdes resultatet upp? → vad hände när problemet rapporterades igen?`

Målet är en ansvarskedja som en extern jurist snabbt kan granska.

Detta är inte ett uppdrag att hitta personer att skylla på. Analysen ska rekonstruera organisationens hantering och besluts-/ansvarskedja utifrån dokumenterade fakta.

## Absoluta metodregler

- Utgå från primärkällor när sådana finns.
- Citera materiellt viktiga uppgifter.
- Skilj individ från organisation.
- Skilj kunskap vid en viss tidpunkt från senare kunskap.
- Skilj aktivitet från relevant utrednings-/åtgärdsinsats.
- Skilj genomförd åtgärd från verifierad effekt.
- Skilj personlig observation från teknisk undersökning, medicinsk bedömning och orsaksutredning.
- Skilj myndighetens bedömning från Familjebostäders tolkning av den.
- Anta inte ansvar enbart utifrån jobbtitel.
- Avsaknad av dokumentation är inte automatiskt bevis för att något inte hänt.
- Ett obesvarat mejl är inte automatiskt bevis för att frågan inte hanterats internt.
- Ett senare negativt resultat bevisar inte automatiskt att ett tidigare beslut var felaktigt.
- Sök aktivt efter omständigheter som talar till Familjebostäders fördel.
- Om slutsatsen inte kan dras: `KAN INTE FASTSTÄLLAS UTIFRÅN TILLGÄNGLIGT MATERIAL.`

## Analysblock som ska byggas

### 1. Aktörskarta

För varje aktör/funktion:

- namn/funktion,
- roll enligt handlingarna,
- vilka delar av ärendet personen hanterade,
- beslut/bedömningar,
- information personen tog emot,
- källor.

Om ansvarig funktion inte kan fastställas: `ANSVARIG FUNKTION EJ FASTSTÄLLD.`

### 2. Kunskapskedja

För varje viktig omständighet:

`datum → information → vem inom FB fick informationen → källa → vad gjorde FB därefter?`

Särskilda informationsområden: lukt, hälsobesvär, symtomlindring efter att bostaden lämnas, andra personers reaktioner, ventilation, blockerade tilluftsventiler, tekniska avvikelser, brand 2017, sanering/dokumentation, OCAB, Miljöförvaltningens observationer, senare vittnesuppgifter och återkommande besvär efter åtgärder.

### 3. Ansvarskedjor per huvudproblem

För varje huvudproblem:

`problem → när fick FB kännedom → mottagare → vem/funktion tog över → åtgärd/beslut → beslutsfattare → underlag → syfte → resultat → effektkontroll → vad hände vid ny rapport?`

Minst följande sakområden ska prövas om primärmaterialet stödjer dem:

- lukt/inomhusmiljö,
- rapporterade hälsobesvär,
- ventilation,
- OCAB/fuktundersökning,
- brand/sanering,
- genomförda och återstående åtgärder,
- senare vittnes-/förstahandsuppgifter.

### 4. Aktivitet kontra relevant åtgärd

Varje aktivitet ska brytas ned i:

`AKTIVITET → SYFTE → RESULTAT → VERIFIERAD EFFEKT`

Exempel: målning är aktivitet men inte automatiskt orsaksutredning. Ventilationsmätning är teknisk undersökning men dess räckvidd får inte utvidgas utöver uppdrag/metod.

### 5. Påståenden om att besvären tagits på allvar

Översätt sådana påståenden till verifierbara organisatoriska frågor:

- när registrerades uppgifterna,
- vem fick ansvar,
- vilken utredning initierades,
- vilken fråga skulle den besvara,
- vilka åtgärder vidtogs,
- hur kontrollerades resultatet,
- vad gjordes när nya reaktioner rapporterades.

### 6. Brukbar sedan dag 1

Rekonstruera:

- första dokumenterade tidpunkt för bedömningen,
- vem som gjorde den,
- underlag och kunskapsläge,
- redan utförda respektive återstående undersökningar/åtgärder,
- om bedömningen upprepades senare,
- om motiveringen förändrades när nytt underlag tillkom.

### 7. Inomhusmiljön är konstaterad fullgod

Identifiera:

- vem som använde formuleringen,
- när,
- vilken undersökning/myndighet som uppges ha konstaterat detta,
- exakt åberopat underlag,
- om formuleringen är direkt från primärkällan eller Familjebostäders egen sammanfattning,
- hur slutsatsen har dragits från underlaget.

### 8. Orsaksfrågan

För varje tillfälle där orsaken efterfrågas:

`datum → exakt fråga → mottagare → svar → åberopad undersökning → dokumenterat uppdrag → besvarade svaret frågan? JA/DELVIS/NEJ`

Ingen medicinsk orsaksbedömning ska göras inom ansvarskartan.

### 9. Eskaleringskedjan

Registrera uttalanden som ”jag tar det med chefen”, ”jag återkommer”, ”jag pratar med förvaltaren”, ”vi tar det vidare”, ”detta behöver undersökas”.

`datum → person → vad skulle tas vidare → till vem → dokumenterad vidarebefordran → resultat → återkoppling`

Om nästa steg inte kan verifieras: `UPPFÖLJNING EJ VERIFIERAD.`

### 10. Platsbesök

För varje platsbesök:

- deltagare,
- uttalat syfte,
- observationer,
- uttalanden,
- identifierade frågor,
- angivna nästa steg,
- faktisk uppföljning.

Personlig observation får inte behandlas som teknisk undersökning, medicinsk bedömning eller orsaksutredning.

### 11. Beslutspunkter

Identifiera vägval:

`datum → beslut/bedömning → beslutsfattare/funktion → kunskapsläge → underlag → motivering → senare utveckling`

Om uppgift saknas: `EJ DOKUMENTERAT I TILLGÄNGLIGT MATERIAL.`

### 12. Åtgärd → resultat → ny information

För varje relevant åtgärd:

`problem → åtgärd → förväntad effekt → effektkontroll → resultat → senare rapporter → FB:s reaktion`

Särskild kontrollfråga: ändrade organisationen strategi när rapporterade besvär fortsatte efter en åtgärd?

### 13. Luckklassificering

Möjliga luckor får klassificeras först efter källkontroll:

- kunskapslucka,
- ansvarslucka,
- utredningslucka,
- uppföljningslucka,
- dokumentationslucka,
- återkopplingslucka.

När endast materialet saknar verifiering används: `kan inte verifieras i tillgängligt material`.

### 14. Closed loop / open loop

**CLOSED LOOP:** problem rapporterat → ansvarig identifierad → undersökning/åtgärd → resultat dokumenterat → effekt kontrollerad → återkoppling.

**OPEN LOOP:** minst ett led saknas eller kan inte verifieras.

Alla open loops ska senare rangordnas HÖG / MEDEL / LÅG efter möjlig juridisk betydelse.

### 15. Motpartens bästa förklaring

För varje möjlig lucka ska Familjebostäders bästa rimliga förklaring formuleras och testas:

- dokumenterad,
- möjlig men ej verifierad,
- motsagd av primärkälla.

### 16. Slutlig ansvarsmatris

`Problem | När FB fick kännedom | Mottagare | Ansvarig funktion | Åtgärd | Underlag | Resultat | Uppföljning | Senare information | FB:s reaktion | Status`

Status:

- SLUTEN ANSVARSKEDJA
- DELVIS DOKUMENTERAD
- ÖPPEN ANSVARSKEDJA
- KAN INTE BEDÖMAS

### 17. Slutprodukter

Efter full analys:

- maximalt 10 viktigaste ansvarsfrågorna till juristen,
- maximalt 5 verifierbara frågor till Familjebostäder,
- en-sidesversion `ANSVARSKARTA – KILSGATAN 3` med vad FB visste, gjorde, bedömde, vilka resultat som dokumenterats, vilka ansvarskedjor som är öppna och vilka frågor som kräver juridisk bedömning.

## Arbetsordning

Arbetet ska göras stegvis:

1. **FAS 1:** identifiera aktörer, funktioner och källor.
2. **FAS 2:** bygg kunskapsloggen – vem visste vad och när?
3. **FAS 3:** bygg ansvarskedjor – information → ansvar → åtgärd → resultat → uppföljning.
4. **FAS 4:** identifiera open/closed loops och testa alternativa förklaringar.
5. **FAS 5:** skapa ansvarsmatris, frågor till Familjebostäder och juristbrief.

Nästa analys ska följa denna ordning och inte hoppa över källkontrollen.
